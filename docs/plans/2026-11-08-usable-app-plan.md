# Usable qJig App Implementation Plan

**Goal:** Deliver a usable local source-grounded app with the existing OpenRouter key, practical limits and a real browser/provider check.

**Scope:** The user removed `GOAL.md` and directed work on a usable app. The old 105-assignment model comparison and research acceptance are optional future work. Preserve historical research data without marking it complete. Use the existing configured key, with a $1 per-request and $25 development ceiling, also constrained by the key and available account credit; retain persistent usage accounting and stop on unresolved paid attempts.

1. **App baseline:** Inspect the current service, UI, configuration and saved-run path; exercise the existing synthetic browser workflow and identify the actual reason real calls are refused. Document current behavior and the intended single-user setup. Do not assume old task status proves usability.
2. **Bounded provider execution:** Implement one practical guarded path from the real app through the existing `OPENROUTER_API_KEY`, persistent local request/goal accounting, journal and OpenRouter transport. Apply the limits above, reserve before sending, preserve usage and uncertain outcomes, prevent automatic retry after a possible send, and never reveal credentials. Do not require the old research campaign, full-account history, a management key, or an allocation for unrelated research. Write failing boundary tests first and verify with fake HTTP, including restart, cap exhaustion and uncertain outcomes.
3. **App workflow and live smoke:** Use the approved configured model and a small non-sensitive sample with a modest per-request cap. Run one real provider request through the actual app path, retain a sanitized receipt and stop on unknown or excessive usage. Exercise import, question, source-linked result/deferral, save and reopen in the real local browser. Keep model interpretations separate from original evidence.
4. **Finish and handoff:** Run focused regressions, the offline suite, applicable browser checks and clean-install smoke. Update user-facing startup/use instructions and the completion report with actual provider and browser evidence, spending, limitations and optional capabilities. Check the scoped diff and secrets. A working app does not imply model superiority, independent validation, a research outcome or production deployment.

For each behavior, use a meaningful failing test, implement the smallest required change, run focused and neighboring regressions, and record evidence. The `plan/app-tasks.json` task list is the execution queue for this amendment. The legacy gate inventory still describes the prior research scope and cannot certify this new goal.
