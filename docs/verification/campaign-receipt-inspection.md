# Retained campaign receipt inspection

`qjig.live_receipts.inspect_campaign_receipts` is an in-process, no-provider-call inspection foundation for an already opened `EvaluationCampaign` and `Journal`. Given a caller-supplied archive directory and reference mapping, it checks the frozen assignment denominator, started/scored state, presence of frozen configuration, goal/journal accounting, aggregate unknown usage and recorded transport labels. For each scored assignment with a reference and archive, it opens `run.sqlite` read-only, reconstructs the score against the supplied reference and stored anchors, and compares the resulting score digest to the campaign record. It does not create absent archive directories or databases.

The result distinguishes `incomplete` missing work, references, archives, usage or live attribution from `invalid` changed scored records or invalid goal/journal accounting. `structurally_complete` is a structural result only. Even if a recorded transport label says live, provider authenticity is explicitly `not_established`; semantic assurance is `not_assessed`. The caller must quiesce the independent stores and supply trusted plan and reference anchors. Hashes do not authenticate their source, prove input bounds, validate source authority, establish independent labels, or establish the value of the resulting decisions.

Synthetic tests cover an entirely unstarted 60-assignment plan, four retained scored assignments, stand-in attribution, missing references, modified archive data and modified journal usage. No model call is made. This module does not implement the complete `scripts/verify_live_receipts.py` gate named in GOAL.md, prove provider-side execution or accounting, independently verify split/label isolation across the full assigned experiment, or authorize a new call. Those requirements remain open.

The inspector also accepts externally supplied configuration and per-run SHA-256 anchors. Missing anchors keep the report incomplete; mismatches make it invalid. For retained scored archives, it rechecks packet limits, applicable source metadata and stage/provider/model/token/price settings against the frozen campaign configuration using the same check as campaign completion. The caller supplies the anchors; matching them does not authenticate their provenance. Configuration and run anchors were exercised with synthetic records, including missing and altered values.

For scored assignments, the inspector additionally accepts caller-supplied external reference hashes by case and external fresh-journal hashes by request. Missing required hashes keep the report incomplete, and mismatches invalidate it. Direct paths whose run digest already binds their journal do not require a separate journal anchor. Synthetic tests exercise matching, missing and altered reference/journal anchors. These checks establish consistency with supplied values, not independent reference quality or anchor provenance.

The inspector can also recheck all declared cases, including unstarted assignments, when given the case root and full case-input mapping. It validates the pinned design and case locks, exact source hashes, declared protected artifacts, externally anchored references, and frozen applicability bindings. Missing case inputs keep inspection incomplete; an incomplete or inconsistent supplied set is invalid. The result labels this as `declared_exact_artifacts_only`: the caller's protected manifest may omit material, and the check cannot detect transformed or paraphrased labels or prove semantic separation.
