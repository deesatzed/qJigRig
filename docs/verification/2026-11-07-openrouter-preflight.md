# OpenRouter preflight research, 2026-11-07

This is a read-only catalog observation, not authorization for inference. No credentials, prompts, completions or paid calls were used. Prices and availability can change; this snapshot cannot authorize a later request.

A public `GET https://openrouter.ai/api/v1/models` listed all four IDs named by GOAL.md: `deepseek/deepseek-v4.1-flash-1017`, `tencent/hy4`, `meta/muse-spark-open`, and `openai/gpt-6.1-terra`. The listed model-level contexts were respectively 1,048,576, 1,048,576, 1,048,576 and 1,050,000 tokens. These are not verified complete-request token counts and exceed the 160,000-token per-request ceiling in GOAL.md; blindly reserving an entire context cannot meet that ceiling.

A public `GET https://openrouter.ai/api/v1/models/deepseek/deepseek-v4.1-flash-1017/endpoints` listed multiple endpoints with differing prices. One listed Fireworks endpoint had prompt/completion prices of $0.45/$1.80 per million tokens, and one BaseTen endpoint listed $0.60/$2.40. The model-level base prices observed at the same time were $0.15/$0.60, with time-dependent overrides up to $0.30/$1.20. Thus a model-level snapshot alone cannot safely bound all eligible endpoint prices. The Hy4 endpoint listing at this observation contained one Tencent endpoint; that is not a guarantee about future routing.

OpenRouter's [provider-selection documentation](https://openrouter.ai/docs/guides/routing/provider-selection) describes routing controls and endpoint variants. Its [price-ceiling guide](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/) describes `provider.max_price` prompt and completion limits in dollars per million tokens. Such a control can be an additional guard against price changes, but qJig now supports it in capped requests, but its enforcement has not been tested here, and it does not by itself prove complete input accounting, all billable categories, or local budget correctness. The [pricing page](https://openrouter.ai/pricing) notes auxiliary charges can still apply and prices can change.

Next preflight work must bind the actual routing and price constraints to the archived physical request, establish conservative complete-input bounds including provider framing, account for every applicable charge and optional service, and reserve the complete required run set. If any bound is unavailable, refuse the paid call and retain unknown cost. Existing `upper_cost` computes arithmetic over supplied metadata; it does not prove that the metadata covers all eligible endpoints or remains current. The live typed path remains disabled.
