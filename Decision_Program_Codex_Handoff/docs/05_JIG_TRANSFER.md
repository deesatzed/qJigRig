# What to transfer from Jig

`reference/jigfiles.txt` is the supplied flat source export. It is included for inspection and reproduction. The audit reconstructed the package, ran all 68 tests successfully in offline mode, and ran additional probes. Treat the exported fixture and results as evidence of a working mechanism on that fixture. Check upstream rights before incorporating third-party code into a distributed project.

| Mechanism | Transfer decision |
|---|---|
| `core.py` and `engine.py` | Use the three-valued logic and inspectable predicate trace as design references. Evaluate exact logic and bounded joint judgments through a common interface. |
| `engine.py` | Carry forward the test of whether an unresolved predicate can change the decision under some completion. Bound evaluation of possible completions. Use it to establish relevance before experimenting with retrieval order. |
| `verify.py` and `reuse.py` | Keep controlled changes to decisive facts, evidence availability, dates, and wording. Make interventions compare both result and decisive evidence. Verify a revision on data reserved for promotion and retain a separate confirmatory holdout. |
| `programs.py` | Keep hand-authored programs as fixtures and diagnostic controls. Preserve candidate, reviewed, active, and prior revisions when implementing the secondary reuse mode. |
| `bench.py` and `web/app.html` | Reuse the idea of a predicate ledger, paired cases, and intervention views. Use real arms and independent scoring for research comparisons. |

## Findings that become regression tests

- **Missing input passed as inapplicable.** A hosting request without a vendor skipped vendor and security predicates and returned approval. Require explicit evidence for inapplicability. Unresolved required inputs defer when material.
- **Historical rule structure was mixed with current structure.** A historical request used the old dollar threshold while evaluating a security condition introduced in the newer program. A separate probe accepted a security review dated after the request. Bind the governing rule structure and time-compatible observations before evaluation. Record how the date was established.
- **Exception search needs an absence policy.** A missing source or no retrieval hit can silently remove an exception. Require a documented basis before treating absence as evidence. Test missing source separately from a decisive negative.
- **Proposal admission needs independent data.** The candidate and patch are prewritten, and some cases described as held out are used during admission. Use separate authoring, promotion, and confirmatory data. Require substantive checks before calling a revision reviewed.
- **A weak direct baseline distorts the comparison.** Jig’s direct arm is scripted and its frontier arm substitutes reference labels. The structured arms both use authored programs. Its `targeted=False` path can still break on a decided expression. Implement separate, accurately named live comparators and a truly exhaustive execution control when testing retrieval savings.

On Jig’s synthetic fixture, after admitting the revised program, both structured arms matched all 15 reference labels. This included one deferral and one escalation. Targeted execution reduced mean predicates evaluated from 4.1 to 3.2, with nine judge-kind evaluations in each arm. The reported 442× figure uses modeled rates and excludes escalation from the smaller path’s average. Neither the benchmark nor the prewritten revision measured the project’s primary claim about fresh smaller-model decomposition versus independent frontier research. Use Jig to test whether the machinery behaves correctly and the live benchmark to test whether it improves real decisions.
