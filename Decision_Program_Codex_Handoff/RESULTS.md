# Results and remaining acceptance work

Snapshot: 2026-11-06. This is a local development workbench for testing models against supplied text, not a validated decision system. [README.md](README.md) contains setup and commands; [PROGRESS.md](PROGRESS.md) is the detailed chronological record. The numbered acceptance criteria are in [the build plan](docs/04_BUILD_AND_ACCEPTANCE.md).

## Verified development evidence

- On macOS arm64 with Python 3.15.2, a clean temporary copy of the current project excluding credentials, data, both virtual environments and caches passed 236 offline tests in a new virtual environment, ran the labeled fixture demo, reproduced the included archive score and served its home page. This was a filesystem copy, not a fresh Git checkout or an accessibility assessment.
- On the same machine, the current 246-test guarded offline suite passed under Python 3.10.18; Python 3.10 also ran the labeled fixture and replayed the included archive score in an earlier check. The optional judge was verified separately on Python 3.12.
- A clean-copy scripted Chromium session saved an adapted public documentation excerpt, ran a direct OpenRouter decision, opened its citation and reopened the saved run. This was one browser path, not independent review.
- The configured OpenRouter planner, direct and frontier arms and the Mac-local typed judge have returned real records. In a public Python documentation shared-corpus development comparison, all three arms returned `issoftkeyword`; the comparison awaits independent adjudication. See [PROGRESS.md](PROGRESS.md) for IDs, settings and reported costs. The local judge threshold is exploratory and local resource costs are unobserved.
- The included [reviewed development archive](examples/shared_corpus_reviewed_archive.json) reproduces its score with `python3 -m workbench dataset-verify examples/shared_corpus_reviewed_archive.json`. Its reviewer was the developer, its journal was not recorded, and the archive is unsigned. It is not an independent benchmark.
- Developer-reviewed intervention examples include changed facts and missing-source deferrals. Those observations demonstrate specific flows, not general causal or semantic correctness.
- A [current-runtime intervention probe](examples/token_current_intervention_probe.json) used a developer-reviewed local-judge program: the original public documentation produced an ISTERMINAL answer, while a synthetic removal of its decisive passage produced a deferral. It is not independently assessed.
- The [public-token comparison export](examples/token_developer_reviewed_comparison.json) demonstrates case assessment and arm review. Its developer reviewer had seen arm identities; the direct quotation was marked unsupported because it omitted the function name, and the local judge's nonlocalized context was marked unclear.
- A synthetic local-judge deferral retained the full source as context and displayed it in Chromium; [the example](examples/local_unknown_context_live_smoke.json) uses a developer-reviewed diagnostic plan. Full-context offsets do not establish a localized supporting citation.
- A [direct OpenRouter probe](examples/token_direct_live_probe.json) on public Python token documentation returned the developer-reference function in one call. Its exact quote omitted the function name, showing the limit of structural citation checks; this is not independent evaluation.
- A [current one-case development dataset](examples/current_dataset_unreviewed_probe.json) completed with the local judge and OpenRouter arms under the frozen-arm checks; it awaits review, and scoring was blocked before adjudication. This is not a benchmark.

## Acceptance status

| Checks | Current evidence and remaining work |
| --- | --- |
| A1–A2: offline startup and real adapters | Full project clean-copy and individual real-adapter smoke evidence exists. A fresh Git checkout was not available; the local judge clean install used cached weights and was verified separately. |
| A3–A6: framing, entity, time and stopping | Deterministic regressions exercise syntax, temporal and expression rules. Model-generated plan completeness, entity interpretation and semantic applicability remain unproven across real tasks. |
| A7: evidence integrity | Exact source bindings are checked, but semantic support and instruction resistance are not guaranteed. The [paired-entity probe](examples/remote_paired_entity_probe.json) records an incorrect model proposal that a lexical guard downgraded to unknown. A [revised-prompt attack variant](examples/instruction_injection_variant_live_probe.json) shows the planner incorporating a forged authority directive and the judge accepting it; the final answer deferred for a separate unresolved fact. A [direct-answer synthetic probe](examples/direct_instruction_live_probe.json) also returned a wrong decided answer after following an embedded grading instruction, despite exact citations to the contradicting facts. A7 is not met. |
| A8: intervention and replay | Fixture and developer-reviewed live paths exist, including a browser missing-source intervention. Replay checks recorded structure rather than rerunning or validating model reasoning; broader controlled and independently assessed intervention coverage remains open. |
| A9: fair comparison | Arms, review gates and offline score replay are implemented. No independently adjudicated held-out set has established comparison quality. The review UI is not a secure blinding boundary. |
| A10: measurement | Provider-reported usage and costs are recorded when available, including failed paths; unavailable values remain unknown. Local resource costs and some provider-side activity are unmeasured. |
| A11: complete app flow | Individual browser and CLI paths for decisions, programs, interventions, review and exports have been exercised; an updated full human walkthrough and accessibility assessment remain open. |

The practical web comparison is experimental and has not been verified end to end with its current controls. A prior provider call exceeded its requested search count; the optional configured tool budget is not a guaranteed dollar cap. An explicit web authorization and budget acknowledgment are required before a new diagnostic. No independently adjudicated pilot or confirmatory non-inferiority result is claimed.
