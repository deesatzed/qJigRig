# Decisions

Status: recommended technical design for review; no combined runtime implemented yet.

- D001: Use qJig as the new repository root and keep both source checkpoints with provenance. QUIXER stays at a named remote checkpoint; source application results are not pooled.
- D002: Build a small modular core behind contracts. Adapt QUIXER's catalog/retrieval and JIG's bounded decision methods through explicit adapters before selective extraction. Avoid merging the two monolithic entry points or giving both stores ownership of the same fact.
- D003: Use one SQLite authority for versioned source metadata and append-only run/event records, plus content-addressed immutable source blobs. Original files are origins; decision runs bind immutable snapshots. A watcher/refresh records new revisions rather than rewriting a running request.
- D004: Store raw-byte hash, decoded-text hash, normalization version and span coordinates separately. Translate legacy QUIXER normalized lines and JIG raw offsets explicitly; never reinterpret a legacy hash as the new canonical hash.
- D005: Preserve true/false/unknown/conflict as predicate states with separate reasons. Missing evidence and budget exhaustion do not become false. Conflict maps to unresolved for reachable-outcome enumeration and remains explicit in the trace.
- D006: Role usefulness changes ordering within evidence acquisition; it cannot eliminate unresolved prerequisites, exceptions, contradictory sources or authority requirements. Task-specific need and applicability take precedence over a role prior.
- D007: Bound graphs initially to six unique predicates, validated depth <=12, AND/OR/NOT only. Exact completion enumeration is feasible at <=64 assignments. A proof of stability applies to the supplied graph only. Structural plan completeness remains an open semantic question.
- D008: First implement deterministic fixture execution and a direct-retrieval control; fresh generative decomposition and local/hosted judges follow behind explicit providers. Keep Hy4 as configured escalation model. Reflex remains optional experimental ordering with fallback while its instability is unresolved.
- D009: Test with the same case/context/role/scope/date and actual resource ledgers. Separate authored programs, fresh plans, reused programs and escalation arms. AI review can guide development but cannot be relabeled independent adjudication.
- D010: Initially use a software-project corpus with authored release rules to test the shared knowledge purpose. This is a reversible starting family, not a promise of a deployment agent or policy authority. Broader task families require their own applicability contracts and evidence.
- D011: Source snapshots are local reference material. No LICENSE was located in the inspected top-level source packages; preserve provenance and clarify distribution rights before publishing substantial copied source. The new core should adapt interfaces and small algorithms with attribution rather than wholesale vendoring into execution.

- D012 (T003, safe assumption): `Budget` has three required limits `max_calls`, `max_tokens` (exact ints, not bool) and `max_cost_usd` (finite int/float); all non-negative, zero allowed meaning no external work of that kind. `Request.budget` is optional; absence is recorded as None, not as an unlimited budget, so later provider code must treat None as "no spend authorized". Field names are provisional until the budget ledger task (P4) confirms them.
- D013 (T005, safe assumption): `revision_id` = `rev1:` + SHA-256 of canonical JSON of {source_id, raw_sha256, text_sha256, encoding, normalizer}. `origin` is recorded but excluded. `source_id` is a caller-supplied logical id and must not be an absolute path, `~` path, drive path or contain `..`. Consequence: the same bytes under two source_ids are two revisions, and the id does not prove who authored or authorized the source.
- D014 (T009, safe assumption): the catalog is one SQLite file (`user_version` 1) holding raw bytes per revision; update/delete are blocked by triggers; reads recompute and verify `revision_id` so on-disk tampering is detected. Re-adding an identical revision from another origin is a no-op that keeps the first recorded origin (origin is provenance, not identity). Triggers are a guard against mistakes, not a security boundary: anyone with file access can drop them (the tamper test does), which is why reads re-verify.
- D015 (T013, safe assumption): index entries live in the same SQLite catalog (schema version 2, additive migration from 1; `store.py` gained generic row methods only). Rows hold offsets and the span's text hash, never source text; loading re-slices the stored revision and fails if the hash differs. Markdown headings use ATX `#` syntax only (no setext, no HTML); fenced code is skipped; a section runs to the next heading of the same or higher level, trailing whitespace trimmed. Heading entries are state `accepted` because they are a deterministic structural reading of the source; generated entries (T014, T015) start `proposed`. Entry ids are SHA-256 of revision, kind, method and offsets.
- D016 (T027, safe assumption): in AND/OR composition a conclusive operand (FALSE for AND, TRUE for OR) settles the result regardless of unresolved siblings; otherwise any unresolved operand makes the result unresolved, and CONFLICT outranks UNKNOWN so a contradiction is not downgraded. All unresolved leaves the result still depends on are returned with their reasons. Plain evaluation treats each leaf independently; shared-reference reasoning belongs to T028.
- D017 (T038, safe assumptions): the CLI is `python -m qjig import|ask|trace` (added `__main__.py`, outside the plan's file list). The ask command takes `--request` (a Request JSON) and `--policy` (plan, entities, as_of, mode, facts, per-predicate needs). Because a CLI cannot receive Python callables, evaluators are declarative: `numeric_threshold` (regex capture + exact comparison via the dated-policy logic) and `phrase_present`, which returns only TRUE or UNKNOWN so a missing phrase is never read as 'no exception exists'. Exit codes: 0 decided, 3 deferred, 2 invalid input. Catalog schema is now v3 (per-revision applicability metadata; first write wins, a conflicting re-import is refused). 'Current' sources are those with live (proposed/accepted) index entries; the latest import of a source id stales older revisions. IMPLEMENT.md mentions a future `run --request --catalog --policy` command after T039; the implemented command name is `ask`.
- D018 (P4, approval interpretation): you were asked whether P4's offline tests may use a labeled stand-in provider transport and replied "proceed with all next steps" after a push. I read that as approval for a stand-in used ONLY to prove journaling, accounting and mapping mechanics (as the build plan specifies). It is named `StandInTransport`, returns authored strings, must be labeled wherever it appears, proves no model behavior, and its removal/replacement by real calls stays on the open-items list. No live call, key, model ID or spend is approved by this. T046 and everything depending on it (T048-T052) wait for your model choice and budget.
